# DreamEval 综合评分首版实施

日期：2026-10-10。依据用户批准的综合公式及 Token 替代费用计分要求；规则以决策文档第 7.3 节为准。

## 政策

版本 `composite-v1-token`。`S = A × (70 + 0.20P + 0.10E)`；资源效率 `E = 0.60K + 0.40T`。Token 基准 100,000，延迟基准 600 秒，超过基准按反比计分，低于基准最高 100。基准是未经校准的初值，不改变 20 分钟 / 80 次请求的执行预算。

Token 使用 Agent 全部调用的输入加输出，缓存输入不重复计算。费用不参与计分，仍保留展示；验收及 Judge 的用量独立报告。延迟使用现有端到端 Agent 指标，包含容器启动与工具预检。

失败任务综合分为 0，原始过程评价保持不变；基础设施/验收异常和证据缺失不算普通失败。成功运行缺少过程、Token 或延迟，综合分为空。无需工具的过程评价不适用仍不自动补分。缺失题目或批次预期重复次数时不发布完整综合分。

## 实现

- `packages/evals/src/dataset/composite.ts` 为浏览器和服务端共用的纯评分模块，独立导出，避免浏览器加载 Node 执行依赖。
- `summarize` 保存政策版本、全部参数、逐次分项、缺失原因、逐题/场景/批次综合分；先平均题内重复，再等权平均题目。
- CLI 和平台批次汇总使用提交时的预期重复次数。比较报告另有综合分可比状态及原因；满足全部条件才返回排名，同分并列。
- 平台总览、场景、批次列表、题目汇总、单次执行及比较展示综合分。实际费用继续展示。
- 读取历史批次时用原始证据重算当前政策，不修改历史执行记录或已保存汇总；新批次保存当前评分汇总快照。

## 验证

31 项相关测试通过，覆盖缓存不重复计算、价格不影响计分、失败与异常区分、缺失/部分遥测、零消耗上限、重复等权、预期次数缺失、排名条件与平台重启后的重算。全仓类型检查和平台生产构建通过。

实际浏览器测试使用两条历史执行记录，在隔离目录验证评分版本、综合分、页面与移动端显示，未重跑 Agent，付费模型调用为 0。这不是新增全量 60 题实测，也不证明初始基准已经校准。
