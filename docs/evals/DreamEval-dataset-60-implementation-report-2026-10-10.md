# DreamEval 60 道数据集实施报告

日期：2026-10-10（Asia/Shanghai）  
数据集：`1.0.1`  
依据：[已确认决策](DreamEval-case-dataset-scoring-decision-2026-10-09.md)与[实施计划](DreamEval-dataset-60-implementation-plan-2026-10-09.md)

新的 60 道题、独立执行协议、验收器、证据采集、过程 Judge 和汇总器已经实现。入库检查为 60/60；真实 Agent 试跑覆盖原先约定的六道样题，共八次：初版六次、环境修订后两次。完整入库与样题试跑是不同结论，不将样题成绩表述为全量成绩。

初始环境保留完整 Click、HTTPX、FastAPI、Fastify、Cobra、Clap 源码、测试、文档与许可证。项目分布分别为 12、20、10、14、2、2 题。Cobra/Clap 用于源码理解、审查与研究，没有声明 Go/Rust 编译运行覆盖。

7 道题以历史上游变更为依据；53 道题是基于真实项目制作的请求。注入缺陷、制作的分支、合成流量均如实标注，不能称为真实用户日志。SQLite 数据、wheel、npm 包、便携服务包、Git 冲突和运行报告均有实际产物。完整仓库上下文提供工程真实性，但不能自动证明高难度；例如类型标记修复的机械难度较低。跨模型区分度尚未建立。

## 验收与复核

49 道题采用程序验收、10 道采用 Judge、1 道采用混合验收。混合题每项标准明确指定程序或 Judge，不重复给分。

| 核验 | 结果 | 证据 |
| --- | --- | --- |
| 程序题参考解、原始环境、不完整解 | 50/50 对照通过，最终矩阵含 150 次程序验收 | 各题 `preparation/CASE-*/controls.json` |
| 参考解修改范围 | 50/50 通过 | 各题 `reference-scope.json` |
| Judge 正确与错误回答 | 11/11 对照通过 | 各题 `judge-controls.json` |
| 工程复核 | 60/60，用户授权的 Codex Agent 复核 | 各题 `engineering-review.json` |
| 验收 Judge 校准复核 | 11/11，Agent 复核 | 各题 `judge-calibration-review.json` |
| 过程 Judge 控制轨迹 | 四组通过：合理工程过程、忽略失败与无效反复、证据不足、轻微错误后恢复 | `preparation/process-controls.json` |
| 入库门槛 | `ready: true`，60/60 | `preparation/admission-report.json` |

用户明确指定 `mimo-v2.5-pro` 用作 Agent 和 Judge，不设本轮费用上限，并指定由 Codex 完成复核。因此所有审核证据都标明 `agent-review` 与 `humanReviewClaimed: false`，没有人工签字或独立模型复核的声明。自动运行复核记录脚本不等于重新完成审查。

复核中修正了几类实质问题：Judge 曾从源码推断提交正确，现要求通过项引用实际提交；部分初始错误对照没有真正失败，现以真实构建或行为修正；验收补充了压缩流边界、连接关闭、空令牌、旧接口拒绝、无效编码、数据库约束、实际测试执行等。逐题记录说明了每道题验证的范围与剩余限制。

## 环境与执行证据

运行使用固定本机 Linux 镜像 SHA256、关闭网络、只读根文件系统及隔离的工作区/home。Python 镜像分别卸载目标 Click、HTTPX 或 FastAPI，避免从预装的同名包读取正确实现；其他运行依赖保留。Node 使用固定离线依赖，生产安装任务另有实际 npm 缓存。

Git 合并题包含真实嵌套 Git 状态，普通 Git 检出无法携带它。其初始工作区与参考状态分别保存为归档，使用 `preparation/restore_git_state.py` 恢复；归档逐文件与实际状态比对通过。恢复脚本不覆盖已有目录，数据集完整性核验会核对恢复后的字节。

数据集 `1.0.1` 摘要为 `85ee4ea79ae70d44124de940c4a9070fcd21df44bee0893b78f8acda03575e9e`，覆盖 36,097 个运行文件。它是一个固定长度的数据集摘要，不在每题增加文件哈希字段；制作记录及运行结果不参与摘要。

真实试跑暴露了 HTTPX 上游测试依赖缺口，`1.0.1` 已补齐 Trio、trustme、TLS、服务器和可选协议依赖，同时仍不预装目标 HTTPX。原始 HTTPX 0.27.0 环境中，141 项解码/响应测试与完整离线测试均可运行；完整离线测试为 851 通过、1 跳过、5 项网络测试取消选择。这 851 项也通过了 Agent 实际使用的受管理工具路径。受影响的 17 道程序题已重做参考/原始/不完整解对照。

记录包含公开任务、工具输入与完整输出、最终回答、实际文件产物、独立可信 Git diff、实际 Git 状态、模型用量和 Agent 延迟。隐含推理不持久化，临时会话 home 在公开证据采集后删除。费用供应商未报告时为 `null`。缺失输出、验收器异常、任务失败分开处理。

不允许修改文件的题目以只读工作区挂载执行，运行证据记录 worker 摘要和只读状态。当前执行协议标记为 `dataset-run-v3`，另补充验收和过程 Judge 各自的耗时、供应商用量及已报告小计；这些消耗不混入 Agent 指标。初版六次试跑及修订后的 `dataset-run-v2` 两次试跑保留原记录，不伪称其已经采集后来新增的遥测。

## 评分与试跑

每次统一为 20 分钟、80 次模型请求。任务验收结果、过程评价和工程指标分别保存。当前过程 Judge `process-v3` 使用工具准确性与路径效率两个 0–4 分维度，必须引用证据，证据不足返回空值；不会把一次失败测试自动判为工具错误，也不会仅根据工具数量扣分。版本 3 明确规定，即时纠正的可避免工具误用也不能获得准确性满分；四组真实模型控制评价分别得到 4/4、1/1、空/空和 3/4。

汇总按 case 等权，重复运行先在同一 case 内求均值。缺失、验收异常及用量缺口分别报告；不同数据集、模型、预算或执行协议不能混合，也拒绝混合有配置和无配置的历史记录。资源报告同时展示所有运行及成功运行的消耗；缺失总量为 `null`，实际已报告的小计单独展示。并行执行的延迟不相加充当墙钟耗时。综合权重与工程指标归一化尚未确定，没有导入旧 63＋37 权重。

明细及原始记录路径见 `preparation/trials.json`，两个版本各自的汇总见 `trial-summary-1.0.0.json` 和 `trial-summary-1.0.1.json`。两个汇总均为非全量诊断结果。新版功能题正常执行了大量测试，仍被明确的输入边界验收拒绝；过程评价较高与任务失败可以同时成立。

以上八次试跑的过程分保留原来的 `process-v2` 标尺。最终执行器进一步移除了嵌套工具字段中的 `rawProvider`、原始供应商片段和私有元数据；此前诊断试跑不能作为完整盲评的跨模型排名依据。复核还发现构建题 Judge 把 `subprocess.check_call(capture_output=True)` 的 API 误用称为 Python 3.9 兼容性问题；错误与返工本身有实际证据，但该归因措辞不准确，保留为 Judge 的已知限制。

独立用量采集通过一次真实验收/过程复评验证，结果见 `preparation/evaluation-telemetry-verification.json`。验收模型为 7 次请求、1,489,006 输入 Token、3,119 输出 Token；过程模型为 5 次请求、382,544 输入 Token、3,204 输出 Token，各自延迟约 109 秒与 118 秒。费用均未报告，保留空值。这是同一条不可变轨迹的评分复评，没有新增 Agent 执行，也没有改写原成绩；其过程分从 75 变为 87.5，暴露了旧标尺对轻微工具错误的满分边界不一致，现以版本 3 的明确锚点和新校准处理，尚不宣称跨模型一致性。

更早的旧版运行记录未混入以上八次试跑。尤其旧构建题曾把内部非零测试退出码表述为整套通过，不能作为全套成功的证据。供应商未报告实际费用，所有收费试跑费用保留空值；初版功能题最后一笔调用没有完整遥测，不能虚构其完整 Token 总量。

## 实现验证与使用

新协议测试 15 项通过，全仓 TypeScript 类型检查通过，eval 包及容器 worker 构建通过。实际容器预检验证了受管理子进程、临时文件写入/截断、只读工作区边界及 HTTPX 完整离线测试，没有调用付费模型。

```powershell
python evals/dataset/preparation/restore_git_state.py
pnpm eval:dataset:worker:build
pnpm eval:dataset validate
pnpm eval:dataset quality
pnpm eval:dataset run CASE-001 mimo-v2.5-pro
```

实现位于 `packages/evals/src/dataset/`；数据、验收与运行说明位于 `evals/dataset/`。旧文档保留在[归档索引](archive/README.md)，活动文档入口已经指向当前决策、实施计划和本报告。

本次完成的是可执行的 60 题数据集及其验证和用户授权的 Agent 复核。后续仍可补充独立人工审查、不同 Judge 的一致性、全量与重复 Agent 运行，以及实测难度分布；本报告不声称这些证据已经具备。
