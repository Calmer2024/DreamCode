# DreamEval 测评组与 20 题框架比较

日期：2026-10-10。状态：测评组已实现、部署及验证；40 次真实执行正在进行，尚无最终综合分排名。

## 设计与实现

测评组是从当前 60 道题中选择并保存的题目集合。评测批次是使用一个测评组、指定 Agent/模型、Judge 和重复次数的一次评测。组不包含模型或评分权重，不改变 case 的六字段结构。

组保存 `id`、`name`、`description`、`caseIds`；平台返回 `builtin` 与自定义组的创建/修改时间。默认完整组动态包含全部题目；内置 20 题组固定选择。内置定义位于 `evals/groups.json`，用户自定义组位于运行目录的 `dataset/web-groups/`，均在数据集完整性目录之外。组不增加或改变 dataset 的题目内容、验收与完整性摘要。

新增“测评组”页面，支持创建、筛选选题、说明、成员预览、复制、编辑及删除。使用现有 Design Token、Radix 图标、选择器、复选框和对话框。新建评测只选择组，不再直接选择题目；题库中的“评测此题”入口已移除。一题的组仍合法，用户可以自行创建。

`GET /api/dataset/groups` 读取组；`POST /api/dataset/groups` 创建；`POST /api/dataset/groups/:id` 编辑；`DELETE /api/dataset/groups/:id` 删除。名称、题目存在性、非空和重复成员由服务端校验；内置组不可修改或删除，写操作检查来源。提交批次使用 `groupId`，服务端解析题目；直接提交 `caseIds` 被拒绝。

批次保存组的 `id/name` 快照和现有 `caseIds` 快照。修改、删除组均不影响历史批次，排队中的执行也使用提交时范围。批次整体评分仍按题目等权汇总；不得把已完成子集当作完整组成绩。

## 本轮执行与评分

Agent 模型与 Judge 模型均为用户指定的 `mimo-v2.5-pro`。每框架 20 题、每题一次，按用户最新要求先 Claude Code 再 DreamCode，平台按题顺序执行。两框架分别使用独立初始工作区，复用同一题目环境、验收器、数据集摘要与预算：20 分钟 / 80 次模型请求。过程政策为 `process-v5`，当前执行协议为 `dataset-run-v6`，其中修正了平台对终止失败及公共 HTTP 传输的处理。

综合评分沿用 `composite-v1-token`：正确性 70%、过程 20%、资源效率 10%。资源效率内 Token 60%、Agent 延迟 40%，基准为 100,000 Token 和 600 秒。失败题计 0；基础设施/验收异常或必需证据缺失不补分。完整比较要求同题、同次数、同预算与 Judge 政策、完整综合分。原生成绩与证据不可变。

两套框架采用各自原生系统提示、工具及子 Agent，因此比较对象是完整配置；单次试跑只能得到本组的初步比较，不证明所有题目上的普遍优势或重复运行稳定性。顺序执行可能受到服务时段变化影响，报告保留时间和用量。

## 首轮异常与重启原因

首轮目录 `comparison-balanced20-79132744-405b-4306-bab2-b06985ff3c21` 保留为 `invalidated`。DreamCode 首题出现 `turn.failed`，错误为 `Internal Server Error`，22 次请求仅 21 次完整用量；平台却因 worker 发送 done 并以 0 退出而误记 completed，随后把未完成修复记为普通验收失败。该记录不能用于评价 Agent 能力。

同一记录的过程 Judge 在 300,420 ms 时抛出 `TypeError: terminated`，没有完整用量。这个时长与 HTTP 传输的默认空闲超时吻合。本地把空闲超时缩短到 1 秒，复现了同样错误及 `UND_ERR_BODY_TIMEOUT` 原因；原始记录未保存 cause，因此不能断言真实连接的所有错误都由此造成。Undici 的默认 300 秒响应体空闲超时见[官方 Dispatcher 文档](https://undici.nodejs.org/api/Dispatcher)。

修复在公共传输中配对同一 Undici fetch/dispatcher，由原调用 AbortSignal 控制截止时间；应用于 DreamCode/Judge 的 SDK 与外部框架桥接，不修改提示、thinking 参数、工具、验收或评分权重。另修复 SDK 在 AbortError 下静默结束迭代时被转换为成功完成的情况；中断后不再提交部分工具调用或生成 done。平台在收到 turn.failed/turn.interrupted 后，即使容器正常退出也上报执行错误，预算耗尽保留原分类，异常不混成普通失败。
